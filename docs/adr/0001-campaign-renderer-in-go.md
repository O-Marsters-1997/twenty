# ADR 0001 — Render campaign emails in Go

Campaign bodies are tiptap JSON that `twenty-emails` turns into HTML and plain text through React Email. Slice 7 deletes the Node server, so a Node sidecar for rendering would be the only thing keeping Node and a second deploy unit alive. We port the renderer to Go instead (`GoRenderer` in `internal/messaging/campaign.go`), covering paragraphs, headings, text, variable tags, hard breaks and the bold, italic, underline, strike and link marks, and returning `ErrUnsupportedNode` for anything else so a campaign never ships with part of its body missing. The port is held to `twenty-emails` by golden files in `internal/messaging/testdata/campaign/`, regenerated from `twenty-emails` with `generate.tsx` (run from `packages/twenty-emails`: `bun run generate.tsx <fixture-dir> <name>`). The cost is that new `twenty-emails` node types (images, buttons, columns, lists) need a Go port when campaigns start using them, and the plain-text output copies html-to-text quirks such as upper-cased headings.
