# ADR 0004 — Biome replaces oxlint and oxfmt, without rule parity

Linting runs through oxlint with per-package `.oxlintrc.json` files, about 25 custom `twenty/*` rules from `packages/twenty-oxlint-rules` and `@stylexjs/eslint-plugin`, and formatting through oxfmt. Speed is not the reason to switch: oxlint is already in Biome's speed class and front lint takes about 16s. We want one tool for lint and format with a fresh config. One root `biome.json` on Biome's recommended defaults covers every TS/JS package, and oxlint, oxfmt, every `.oxlintrc.json` and the `twenty-oxlint-rules` package are deleted. This is an overhaul, not a port: the custom rules (module boundaries, no hardcoded colours, component props naming, folder structure and the rest) and the StyleX rules are dropped, not rewritten as GritQL plugins, and we accept that conventions they enforced are no longer checked. Front lint's type-aware oxlint rules (such as `strict-boolean-expressions`) go too, since Biome's defaults have none; the tsgo typecheck remains the type gate. The switch lands in one PR: format and apply safe fixes repo-wide, then disable in `biome.json` any rule still failing, with a follow-up ticket to re-enable each. CI is green from the first day, and the remaining debt is listed in tickets. If it collides with the Vitest migration, Biome's reformat merges first.
