# ADR 0002 — Go auth shares Node's Redis for login-token markers and session cache

Node marks a login token consumed with `SET NX PX` on `<REDIS_CACHE_PREFIX>:engine:auth-session:login-token:consumed:<jti>` and caches resolved user sessions under `<prefix>:engine:auth-session:<tokenHash>` for 60 seconds. Until slice 7 removes Node, a login token consumed by Go must not replay on Node and the reverse, and a session Go revokes must not stay valid in Node's cache. A Postgres table cannot give either guarantee, because Node never reads it, so Go adds go-redis (`REDIS_URL`, `REDIS_CACHE_PREFIX`) and writes Node's own keys through `auth.RedisCache`: `SetIfAbsent` stores JSON `true` with the login token lifetime, and session revocation deletes the cached `<tokenHash>` after the Postgres update. A Redis outage fails login-token consumption and cache deletion closed, with an error instead of a silent accept. Throttling stays in `MemoryThrottle`: Go and Node count attempts separately until slice 7, which doubles the effective OTP and recovery-code limits during the overlap and does not allow replay. After slice 7 the markers can move to Postgres or stay in Redis. The only new test dependency is miniredis, used in `cachestore_test.go` to hold the key layout and TTL against what Node writes.
