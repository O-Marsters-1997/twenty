# ADR 0003 — moon replaces Nx as the task runner

CI runs every check through `npx nx`, but the repo uses little of Nx: eight projects of mostly `nx:run-commands` targets, the `@nx/jest`, `@nx/vite` and `@nx/vitest` executors, `^build` dependencies and the local cache, with no `affected`, tags, inference plugins or Nx Cloud (#153). We replace Nx with moon v2, configured by hand rather than with the experimental `moon ext migrate-nx`: a fresh `.moon/workspace.yml`, a toolchains file for Bun and Go, and one `moon.yml` per project with explicit `inputs` on every task, because moon's default `**/*` inputs would hash too much. CI keeps explicit, named jobs that call `moon run`, moon's affected detection replaces the tj-actions changed-files filter, and `actions/cache` persists `.moon/cache` so build, lint, typecheck and test can all replay from cache when their inputs are unchanged. We chose `actions/cache` over a Bazel remote cache to avoid running infrastructure or adding a third party, and accept GitHub's 10 GB eviction and a lower hit rate. The Nx cache step planned for phase 1 is dropped, since moon replaces it. Every `nx` call site moves to moon in the same change: CI, `.claude/hooks/deny-ci-commands.sh`, CLAUDE.md, `setup-dev-env.sh`, generated-file headers and the README. `@nx/react` generators go with no replacement.
