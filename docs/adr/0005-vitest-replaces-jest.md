# ADR 0005 — Vitest replaces Jest in every package

Front jest is on the CI critical path (about 104s of tests per shard, plus a custom `jest-stylex-transformer.cjs` wrapping `@swc/jest` and a hand-kept `transformIgnorePatterns` list). twenty-ui already runs unit tests on Vitest. We move twenty-utils and twenty-emails, then twenty-shared, then twenty-front to Vitest one package at a time, so Jest leaves the repo entirely, each flipping fully with no period of running Jest and Vitest side by side. twenty-front adds a jsdom `unit` project to its existing `vitest.config.ts` beside the Storybook project, reusing the app's Vite plugins (StyleX, Lingui) the way twenty-ui does. The custom transformer and `transformIgnorePatterns` go, and `jest.*` calls move to `vi.*` by codemod. A suite the codemod cannot fix gets `describe.skip` with a linked issue, capped at about 2% of suites, and the front PR does not merge above the cap. Whether to move from 3 front test shards to 4 is decided after the migration, by measurement: add a shard only if it cuts the critical path by 20s or more.
